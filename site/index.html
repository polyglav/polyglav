Terminal-native agent core

One agent,
many heads.

Describe the outcome once. Polyglav breaks it into steps and hands each one to a specialist agent, working in order in one process. Use it in the terminal when you want. Put it on a server and let it work. No dashboard to watch, no chat window to keep open. Files, web, commands, code and git, behind permissions you set.

Install

curl -fsSL https://raw.githubusercontent.com/polyglav/polyglav/refs/heads/main/install.sh | sh polyglav

Installs with uv or pipx when available, otherwise pip. Adds pip or Windows readline support when missing.

01 / WHY POLYGLAV

Built to be boring
where it matters.

No browser, no account, no dependency tree. A small core you can read, with every action on the record.

STRUCTURED

Compose a team

Ask for an outcome, split it across specialist roles. Run them sequentially, or manage hierarchically when the work needs it.

AUTOMATED

Unattended by design

Wait for the end result, put it on a server with a schedule, or run it as a fleet. Results land in append-only logs and optional webhook reports.

SECURE

Safe by default

Allow, ask, or deny by tool and category. File access outside the project is scoped, and every action lands in the session log.

LIGHTWEIGHT

Zero dependencies

Pure Python standard library, no supply chain, and local-first. Keys, sessions, roles, and config stay on disk as text, with any provider you choose.

Works with Anthropic, OpenAI, Groq, Ollama, OpenCode, and any OpenAI-compatible cloud or local endpoint.

03 / HOW IT WORKS

Ask once.
It does the handoffs.

One loop, one stream, one prompt. Specialists run one after another in the same process, each with its own context and permissions.

  1. ASK

    Start with one outcome

    Describe an outcome in one sentence, the way you would to a colleague.

  2. COMPOSE

    Design the team

    For bigger work it designs a small team and the order its members run in.

  3. RUN

    Give each stage its own scope

    Each stage gets its own context, tool access, model, and session.

  4. CONTINUE

    Carry every result forward

    Every result feeds the next specialist, without switching windows.

04 / RUN IT ANYWHERE

The UI is optional.

Polyglav is the worker, not the window. Give it a project, a permission boundary, and a schedule, and it keeps working after the window closes.

INTERFACE

Terminal, IDE, web UI, or another agent

Use the REPL, a script, an editor, or a UI built by someone else.

CONTRACT

CLI, HTTP API, MCP

Full turns, direct tools, sessions, and control.

WORKER

One runtime

Roles, teams, jobs, fleet, and append-only logs.

CATALOG

It configures itself

In write mode, the assistant creates roles, teams, and skills through the catalog. The caller can do the same.

HEADLESS

The UI can close

The server, scheduler, and fleet keep running after the window closes.

POLICY

The policy travels

The same mode and tool policy apply to every caller, whichever interface starts the work.
