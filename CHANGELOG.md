# Changelog

## v0.38.0 - 2026-09-29

- Ollama null-content fix - an assistant turn that only made tool calls, or only produced reasoning, is now serialized with an empty `content` instead of `null` (`turn_to_provider`), and `OpenAICompatibleProvider._prepare_messages` coerces a null assistant content to an empty string. A session with any tool-using turn no longer 400s on Ollama's OpenAI-compatible endpoint (`invalid message content type: <nil>`), which had made every later request in the session fail. Tests: `tests/test_turns.py`, `tests/test_providers.py`

## v0.37.0 - 2026-09-27

- Renamed the project from Replio to Polyglav - the Python package (`src/polyglav`), the `polyglav` CLI and `python -m polyglav`, the worktree directory (`.polyglav/`), the global config directory (`~/.config/polyglav/`), the `POLYGLAV_*` environment variables, the bundled `polyglav-core-*` plugins with their `polyglav_version` manifest field, and all repository, PyPI, and documentation URLs. Existing `.replio/` configs and sessions are not migrated.
- Rewrote the README around outcomes with the "One agent, many heads" slogan and moved the technical quick start, CLI, API, swarm, jobs, fleet, MCP, Docker, and plugin material into a new `INSTALL.md`.

## v0.36.0 - 2026-09-24

- Fixed scoped `code_test` no-match detection on Python 3.11 - the dev wrapper now also treats `Ran 0 tests` in the output as no tests, because the `NO TESTS RAN` message and exit code 5 for a target with no tests were only added in Python 3.12. A scoped run on 3.11 now reports `no tests matched "<target>"` instead of looking like a passing check. The test no longer asserts the 3.12-only message or exit code, which also unblocks the all-plugins run on 3.11. Tests: `plugins/replio-core-dev/tests/test_tools.py`
- Tool identity, error color, compact status params - the `git`/`git_commit` tools now print as `⎇ Git` with their own glyph instead of `← Read`, and the dev wrappers print `$ Test`/`$ Lint`/`$ Format`. A new `error` registration predicate marks a result as failed (`run_command` and the dev wrappers read the `exit N` line), and the agent loop renders such an echoed result red through `ReplUI.tool_error_result` rather than dim. `ToolRegistry.params_str` renders an oversized or multiline argument as `<N chars>` instead of dumping a body into the glyph status line or the confirm label. Docs (`tools.md`). Tests: `tests/test_ui.py`, `tests/test_tool_registry.py`, plus the git, dev, and exec plugin suites
- Optional output log - `output_log` (default `false`) tees everything the REPL prints into `.replio/output/<session>.txt` (directory set by `output_log_dir`), ANSI colors included, so a mis-rendered line can be inspected later. A new `TeeStream` in `ui.py` wraps `sys.stdout` for the run and skips spinner repaints (writes with `\r` and no `\n`) and readline markers. Docs (`config.md`). Tests: `tests/test_repl_input.py`
- Renamed types to roles - the agent catalog now uses one vocabulary: `AgentType` is `Role`, `TypeRegistry` is `RoleRegistry`, `src/replio/types.py` is `roles.py`, `bundled_types.json` is `bundled_roles.json`, `docs/types.md` is `docs/roles.md`, and the catalog files are `roles.json`. The `/types` command is `/roles`, a new `/role` command reports the active run's role and session, `--type` is `--role` (`replio run`/`replio fleet config`, jobs), the plugin hook is `register_roles`, and the `delegate` tool argument, the `catalog` tool `kind`, and the team stage field are all `role`. The `assistant_type` config key is `assistant_role`. No compatibility aliases, so existing `.replio/types.json` and `teams.json` files with the old keys are adapted by hand. Docs synced across `docs/`, `AGENTS.md`, `README.md`, and `VISION.md`. Tests renamed (`tests/test_roles.py`)
- Visible sub-run stages and stats - a delegated agent or team stage now leaves a dimmed `✓ <stage> (Ns, N tokens)` line when it finishes instead of erasing the animated status line, so a multi-stage run shows its progression rather than only the last stage. `ReplUI.status_end` takes an optional note, `Engine._run_stats` derives the duration and token total from the turn's usage, and the `NullUI`/`BufferUI`/`HeadlessUI` sinks take the note too. A new `subrun_verbosity` config (`quiet` default, `summary`, `full`) controls how much of a sub-run reaches the terminal: `summary` uses the new `SubRunUI` to forward only the sub-run's write and edit activity lines while its full output still buffers for `/focus log`. Docs (`config.md`). Tests: `tests/test_ui.py`, `tests/test_team_run.py`
- Reliable REPL prompts and multi-line input - the tool confirm and `ask` are line-based with validation instead of raw single-key reads, so an answer is always taken and a redirected stdin never hangs. The confirm accepts `y`/`yes`/empty as yes and `n`/`no` as no, re-prompting on anything else, and its hidden path only applies to the confirm (a free-text `ask` answer stays visible). The `ask` tool registers `confirm=False`, a new registry metadata flag, so a question is never gated by its own confirm prompt and the loop proceeds straight to it. Multi-line input closes on a delimiter at the start of a line or on a blank line instead of the odd-count quote heuristic, so a backspace or a pasted delimiter no longer submits mid-typing, and a trailing `\` continues the message on the next line. Docs (`tools.md`, `README.md`). Tests: `tests/test_ui.py`, `tests/test_ask.py`, `tests/test_unattended.py`, `tests/test_repl_input.py`
- `vcs` permission category - `git_commit` moves off the `edit` category onto its own `vcs` category (default `ask`), so the commit tool is gated by its own carve rather than by general file edits. Its per-invocation resolver now returns `ask` only when `all` is true and otherwise returns `None`, which defers to the category action, so a role whose carve sets `vcs: allow` commits without a prompt while every other role confirms (`ask` auto-denies in a sub-run). Staging everything with `all=true` always asks, so an unattended commit never sweeps unrelated work. Docs (`AGENTS.md`, `config.md`, `security.md`, `tools.md`, `writing-tools.md`). Tests: `plugins/replio-core-git/tests/test_tools.py`, `tests/test_config.py`
- Scoped `code_test` runs - `code_test` with a `target` now runs that target instead of appending it to a unittest `discover` command, which previously matched nothing, exited 5, and printed `NO TESTS RAN`, so a scoped run verified nothing while looking like a completed check. When the configured `dev.test_cmd` is the unittest discover form, the wrapper builds `python -m unittest <target>`, and any other command still appends its target. A target run that reports no tests appends `Error: no tests matched "<target>" (unittest exit 5)` to the tool result, and the dev wrapper's `DEFAULT_TIMEOUT` rises from 120 to 300 because the full suite takes about 144s. Tests: `plugins/replio-core-dev/tests/test_tools.py`
- Config merge - nested config objects now merge per key across the built-in defaults, the global config, and the local config (`tool_permission`, `modes`, `ask_policy`, `memory_scopes`, `grant_permission`), so a local object overrides only the keys it names. Lists and scalars still replace wholesale. The default `ask`, `catalog`, `handoff`, and `team` permissions are no longer dropped when a local `tool_permission` is set, which had confirm-gated those tools because `ToolPolicy` falls back to `ask` for a missing category, and `Config.unset` recomputes the key from the remaining layers. Docs (`config.md`). Tests: `tests/test_config.py`, `tests/test_modes.py`
- Dimmed thought summary - the `(Thought N.Ns)` line printed after streamed reasoning is dimmed again, so only the `- Thinking` header (reasoning shown) and the `+ Thought N.Ns` line (reasoning hidden) stay blue. Docs (`config.md`). Tests: `tests/test_ui.py`

## v0.33.0 - 2026-09-16

- Job and delegation session naming - job runs and delegation sub-agents now embed the same six-character run code, so generated runs are `job_<ts>_<code>` and `sub_<ts>_<code>`. The job name and the parent session id are dropped from the filename: the job name stays in the job registry and each run's `JobRun.session`, and the calling session stays in `parent_id`. `coded_name`/`name_code` in `sessions/manager.py` mint and parse the code (`_sub_session_name`, `job_session_name`), a name collision re-mints instead of appending `_2`, and `SessionManager.create` derives a coded name's code automatically. Warm `sub_<key>` member sessions and `agent_<role>` role sessions keep their stable deterministic names, their code naming is a follow-up task. Docs synced (`session.md`, `jobs.md`, `swarm.md`, `teams.md`, `security.md`, `testing.md`, `usage/programming.md`, `AGENTS.md`). Tests: `tests/test_run_code.py`, `tests/test_jobs.py`, `tests/test_subagent.py`
- Stable run code and `ses_<ts>_<code>` naming - every session now carries a six-character base36 `code`, minted at creation and stored on the session (`Session.code`, `Run.code`). Auto sessions are named `ses_<ts>_<code>` from the start, so the prompt-slug rename (`_auto_name_session`) and its transliteration logic are gone and a session name never changes. The code is a durable handle across restarts: commands accept it as `#code` (`/focus #ab12cd`, `handoff` target `#ab12cd`, `/history --run #ab12cd`, `/print --run #ab12cd`) and it is shown by `/focus`, `/history`, and the run log. Resolution checks live runs first, then `SessionManager.find_by_code` globs the sessions directory for `*_<code>.json` - no session files are read to find it. `Engine.chat` loses the now-redundant `autoname` parameter (the name is final at creation), and `load_or_create_session` syncs `run.session`/`run.code`. Explicit names (`/session new`, `--session-id`) carry no code and are referenced by `session:<name>`, and legacy files resolve by name only. Docs synced (`session.md`, `architecture.md`, `commands.md`, `tools.md`, `testing.md`). Tests: `tests/test_run_code.py`, plus code assertions across the suite
- `/print` command - reprints a listed turn in full or one part of it. `/print <n>` shows the turn's full metadata block (`#index`, status, duration, tool count, `started`/`ended`, model, provider, mode, reasoning - empty values as `-`, so a command turn is self-describing), then each part in order: the operator prompt, thinking (dim), every tool call with `input` JSON, `output`, `is_error`, and `analysis`, the answer, command records (compaction summary included), and system notes. `/print <n>.<m>` prints only the m-th part. Each part's text is capped per part by the new `print_max_chars` config (default 4000, `0` = unlimited) with `... (N more chars, use --full)` appended, and `--full` drops it for one call. `--run <#id|role|session:name|name>` reuses the `/history` target resolver to read another run without switching focus or the current session. The line renderer `render_turn` lives in `sessions/render.py`. Docs synced (`commands.md`, `session.md`, `config.md`, `testing.md`). Tests: `tests/test_print.py`, `tests/test_session_render.py`
- `/history` command - lists the active session's turns as a numbered, printable index, one line per turn: `#<index>  [<status>]  <duration>  <tool count>  <prompt>`. The index is the turn's absolute `index`, so a turn can be named later regardless of the listing limit. `/history 3` shows the last three turns (default 10), `/history all` every turn, and `--thoughts` adds a dim first-line excerpt of the turn's thinking (`--thoughts all` prints the full text). `/history --run <#id|role|session:name|name>` reads another run's session without switching focus or the current session: an id resolves to the live focused run when present, otherwise the saved session, a role resolves to its live `agent_<role>` engine or the saved session, and a bare name resolves to the saved session (legacy flat-`messages` files read as not found). The line renderer `turn_summary` lives in `sessions/render.py` and the target resolver `_target_session` in `commands/builtins.py`, shared with the upcoming `/print`. Docs synced (`commands.md`, `session.md`, `testing.md`). Tests: `tests/test_history.py`, `tests/test_session_render.py`
- Session turn cutover - session logs now store turns only, and the flat `messages` format is removed everywhere. A turn is one operator prompt (or one slash command) and the agent's response: `{index, started_at, ended_at, status, model, provider, mode, reasoning, parts}`. Parts are typed (`user`, `text`, `thinking`, `tool`, `command`, `system`), and a `tool` part co-locates a call with its result (`name`, `input`, `output`, `is_error`, optional `analysis`). `Session` exposes an explicit turn/part API (`start_turn`/`end_turn`/`add_part` and `add_user`/`add_system`/`add_thinking`/`add_text`/`add_tool`/`add_command`) that replaces `add_message`. The engine opens a turn with the user part, co-locates each tool call with its result, closes the turn with its status, and rebuilds the provider context from turns through `turns.provider_messages` (assistant text plus consecutive tool parts grouped into one `tool_calls` message with its results, thinking attached, command parts dropped, compaction summary plus turn-index boundary). The renderer, Markdown export, `/sessions` preview, and the secondary readers (`delegate` result summary, `ask` task preview, run and team memory summarization, eval error count) all read turns. `compact_keep` now counts turns. Existing `.replio/sessions/*.json` files with `messages` are left untouched and no longer load (`read()` returns nothing, the name stays listed). Docs synced (`session.md`, `architecture.md`, `config.md`, `security.md`, `testing.md`, `writing-tools.md`, `AGENTS.md`). Tests: `tests/test_session_log.py`, `tests/test_session_render.py`, plus turn-model migrations across the suite
- Session turn model - a new `src/replio/sessions/turns.py` defines the turn/part shape for the session rewrite. A turn holds `index`, `started_at`, `ended_at`, `status`, the turn-level `model`/`provider`/`mode`/`reasoning`, and an ordered `parts` list. Builders cover the six part types (`user`, `text`, `thinking`, `tool`, `command`, `system`), a `tool` part co-locates `name`/`input`/`output`/`is_error`/`analysis`, and `provider_messages` rebuilds the OpenAI-compatible context by grouping a turn's text and consecutive tool parts back into one assistant `tool_calls` message plus its tool results, dropping command parts and applying the compaction summary and turn-index boundary. The module is wired into `Session` and the engine by the turn cutover above. Docs synced (`testing.md`). Tests: `tests/test_turns.py`

## v0.32.0 - 2026-09-15

- `focus_on_delegate` config - `off` (default), `ask`, or `on` moves the REPL focus to the delegated role's engine after a `delegate` call. With `on` the tool records a pending focus that `ChatLoop` applies after the turn, so the caller's answer still finishes and the next input goes to the specialist. With `ask` the operator is prompted first (skipped under unattended mode), and an unrecognized value falls back to `off`. Focus is REPL-only, so a sub-agent that delegates is a no-op, and a focused role engine that delegates follows too. Docs synced (`config.md`, `architecture.md`, `swarm.md`, `testing.md`). Tests: `tests/test_focus_on_delegate.py`
- `handoff` tool - a core tool (category and permission `handoff`, default `allow`) lets an agent pause or finish its run and hand control to another run, with the operator's focus following. `target` resolves against the run registry as `parent`, `child`, `sibling`, a role name, `root`, or a run id (`3` or `#3`), and `done` (default false) finishes the current run instead of leaving it `paused`. The tool records a pending handoff and the agent loop stops after the tool batch, so no further provider round runs. `ChatLoop` applies the pending handoff once the turn returns, focusing the resolved role's engine (a root-role target resets to the assistant). It is REPL-only: a delegated sub-agent has no focus manager and gets a clear error. Docs synced (`tools.md`, `config.md`, `architecture.md`, `testing.md`). Tests: `tests/test_handoff.py`
- `/focus` command - shows the current run, the run tree (indented, current marked), and the flat call log, then attaches or moves through the run registry. Attach by run id (`<id>`, `#id`), role (the stable `agent_<role>` engine), or `session:<name>`, and navigate with `parent`, `child [n]`, `sibling [n]`, `next`, `prev`, and `back`. Focusing a run attaches to the role engine that owns it, and a root-role run resets to the assistant. Focus is REPL-only. Docs synced (`commands.md`, `architecture.md`). Tests: `tests/test_focus.py`
- Focus manager and role engines - the REPL keeps a focus stack (`FocusManager`, `src/replio/focus.py`): the root assistant plus a role engine per focused role. `ChatLoop.active()` returns the focused engine and `ChatLoop.run()` routes turns and slash commands to it, so one window drives whichever agent is in focus. `Engine.focused_engine(role)` builds a role engine with the same type resolution, skills, and permission carve as a delegation sub-agent, but with the REPL UI and a stable `agent_<role>` session that resumes on re-focus, and it records a run. `back()` and `reset()` walk the stack and repoint `ReplUI._loop` so rendering and confirms follow the active engine. A new `prompt_role` config (default false) prefixes the prompt with the active role (e.g. `Assistant >>>`). The per-engine run attribute is `current_run` so it no longer shadows `ChatLoop.run`. Docs synced (`architecture.md`, `config.md`). Tests: `tests/test_focus.py`
- Run registry and call tree - every engine instance is a run in a process-local `RunRegistry` (`src/replio/runs.py`) shared across the delegation tree: numeric `id`, `role`, `session`, `parent` and ordered `children`, `status`, the `task` brief, and timestamps. Delegated and team-stage engines register as children of the caller and are finished when their `chat` returns, `RunRegistry.runs()` is the flat creation-order call log, and `children(id)` walks the tree. This is the data model the focus and handoff surface builds on. Docs synced (`architecture.md`). Tests: `tests/test_runs.py`
- Session role metadata - every session records the agent type that owns it as `role`, stamped at creation: the bound root type (`Engine.bind_root_agent`), the delegated and team-stage type (`_new_sub_engine`), and the job type (`scheduler._build_engine`). `/session new` carries the current role. A plain root or a headless run with no `--type` leaves it empty, and legacy files without the key load with an empty `role` (no backfill), so a run is reconstructable from its log. Docs synced (`session.md`). Tests: `tests/test_session_log.py`, `tests/test_assistant.py`, `tests/test_subagent.py`

## v0.31.0 - 2026-09-12
