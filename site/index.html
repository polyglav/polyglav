Describe the outcome once. Polyglav breaks it into steps and hands each one to a specialist agent, working in order in one process. Use it in the terminal when you want. 02 / HOW IT WORKS

Ask once. It does the handoffs.

One loop, one stream, one prompt. Specialists run one after another in the same process, each with its own context and permissions.

  1. 01

    Ask

    Describe an outcome in one sentence, the way you would to a colleague.

  2. 02

    Compose

    For bigger work it designs a small team and the order its members run in.

  3. 03

    Run

    Each stage gets its own context, tool access, model, and session.

  4. 04

    Continue

    Every result feeds the next specialist, without switching windows.

  5. 05

    Operate

    Give it a project, a boundary, and a schedule. Check /status, the log, or a webhook report when you come back.

03 / UNATTENDED

Set it once. Let it work.

Polyglav does not ask you to sit in a chat window or watch a dashboard. It is a worker you point at a job. Give it a project, a permission boundary, and a schedule, put it on a server, and let it work. No dashboard to check and no chat window to keep open.

  • Configure onceProvider, model, mode, and permissions in .polyglav/.
  • Schedule oncepolyglav jobs add, then polyglav jobs approve.
  • Leave itpolyglav jobs daemon, polyglav fleet up --detach, or polyglav serve.

Check in when you want: /jobs status, GET /health, the append-only session log, or a webhook report. The report hook is a plugin surface, so email, Telegram, or Signal delivery can be added without changing the core.

$ polyglav jobs add nightly --cron "0 2 * * *" --prompt "update the changelog"
Added job: nightly [proposed]
  schedule: cron '0 2 * * *'
  status:   proposed - approve it to activate

$ polyglav jobs approve nightly
Job nightly: status=approved, enabled

$ polyglav jobs daemon
job scheduler started - press Ctrl-C to stop

Or serve the same loop over HTTP with polyglav serve, or supervise many folders with polyglav fleet up --detach.

04 / WHY POLYGLAV

Built to be boring where it matters.

No browser, no account, no dependency tree. A small core you can read, with every action on the record.

01

Unattended by design

Use it in the terminal when you want. Put it on a server and let it work. Headless CLI, HTTP API, and bundled jobs and fleet plugins for schedules and supervision. Results land in append-only logs and optional webhook reports. No dashboard to watch.

02

One prompt, many heads

Ask for an outcome. Polyglav splits it across specialist roles, runs them in order, and loops a producer against a reviewer when the work needs it. Roles and skills stay reusable, and plugins extend the core.

03

Safe by default

Allow, ask, or deny by tool and category. File access outside the project asks first, a non-loopback API bind needs a token, and every action lands in the session log. The agent can ask you a question mid-run.

04

Zero dependencies

Pure Python standard library. No supply chain, no lockfile churn. The code that runs is the code in the repository.

05

Your machine, your config

Keys, sessions, roles, teams, skills, permissions, plans, todos, and bounded memory stay on disk as text. Bring your own provider or run local. MCP adds more tools when enabled.

06

It does the work, everywhere

Files, web, shell, code, and git, all permission gated. The same loop runs in the REPL, the CLI, and the HTTP API.

05 / PROVIDERS

Any model, any endpoint.

Point Polyglav at an endpoint and it detects the provider. Keys stay on your machine, never in the page, never in a session log.

  • AnthropicClaude models through the Anthropic API.
  • CloudAny OpenAI-compatible cloud endpoint, gateway, or custom base URL.
  • GroqHosted open models on Groq.
  • LocalOllama, LM Studio, or any OpenAI-compatible localhost server.
  • OllamaLocal daemon or Ollama Cloud.
  • OpenAIOpenAI models through the OpenAI API.
  • OpenCodeOpenCode Zen and OpenCode Go, one API key.

Hover a provider to see what it covers. Cloud is any OpenAI-compatible endpoint or gateway. Local is Ollama, LM Studio, and other localhost servers.

Switch models mid-session with /model, or connect a new endpoint with /connect.
